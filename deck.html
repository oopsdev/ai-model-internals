AI 模型的完整生命週期

模型只是 ML 系統的一部分。資料品質、驗證方式與部署條件，同樣決定最後的結果。

AI、機器學習與深度學習

  • AI：讓機器表現出智慧行為的整個領域。
  • ML：不手寫規則，而是從資料學出規則或參數。
  • 深度學習：用多層神經網路學習；CNN、RNN、Transformer 都在這裡。
  • GBDT／LightGBM：用很多棵決策樹，是表格資料的主力之一，但不是神經網路。

「深」指的是多層堆疊，不是指模型比較聰明。

延伸閱讀：教材首頁：AI／ML／深度學習定位

只放常見的模型名稱，避免變成演算法目錄。強調 GBDT 的位置：後面第 15 頁會拿它和神經網路對照。

模型究竟學到什麼

訓練完成後，模型檔裡存的是什麼？依模型家族而不同。

模型家族訓練後保存的內容
線性模型每個特徵一個係數，加上偏置
神經網路每層的權重、偏置，以及正規化層的參數
決策樹每個節點用哪個特徵切、門檻多少，以及葉節點的輸出
GBDT多棵樹的結構與葉值；預測時把所有樹的輸出相加

訓練 ＝ 先選定模型家族（假設空間）與損失函數，再用資料在這個家族裡找出損失低、又能泛化到新資料的那一個模型。

延伸閱讀：教材首頁：訓練一個模型在做什麼

「學到的東西」可能是連續參數（權重），也可能是結構與規則（樹的切分）。共同點：都由「損失函數＋資料」決定。泛化靠驗證資料、正則化與複雜度控制，第 10 頁會講。

訓練與推論

推論只用已學到的模型；訓練才會計算梯度並更新參數。所以同一批資料，一次訓練步驟比一次推論貴得多。

延伸閱讀：02 模型訓練與神經網路 §5、§7、§9

「訓練比推論貴」是指同一模型、同一批資料的單次步驟；產品上線後的總推論量可能遠高於一次訓練。GBDT 沒有反向傳播，但同樣是「訓練時搜尋、推論時固定」。

模型反覆使用的數學工具

這一頁不推導公式，只先知道每種工具在模型裡扮演什麼角色。

數學工具在模型中的用途之後出現在
向量與矩陣表示一筆資料、一層權重，並一次算完整批資料神經元、Transformer
內積衡量輸入和「樣板」有多對齊神經元、卷積、注意力
機率表示不確定性與各類別的可能性sigmoid、softmax、取樣
損失函數把「預測和答案差多少」變成一個數字MSE、cross-entropy
導數與梯度指出每個參數該往哪個方向、調多少反向傳播、SGD／Adam、GBDT

延伸閱讀：01 數學基礎 §1–4

內積是貫穿全場的主角：神經元算的是輸入與權重的內積、卷積是滑動的內積、注意力是 query 與 key 的內積。

一顆神經元到一層網路

$$z=\mathbf{w}^{\top}\mathbf{x}+b,\qquad a=\phi(z)$$

  • $\mathbf{x}$：輸入特徵
  • $\mathbf{w}$：學到的權重（每個輸入有多重要）
  • $b$：偏置，調整觸發門檻
  • $\phi$：激活函數，提供非線性（如 ReLU）

一層 = 很多顆神經元一起算

$$\mathbf{z}=\mathbf{W}\mathbf{x}+\mathbf{b}$$

$\mathbf{W}$ 的每一列就是一顆神經元的權重；一次矩陣乘法算完整層。

延伸閱讀：01 數學基礎 §1.2–1.3；02 §7–8

z 是內積：輸入和權重越對齊，z 越大。沒有非線性 φ，疊再多層也只等於一層線性變換。

模型如何知道自己錯了

模型輸出預測，再拿正確答案（label）比對，算出一個損失值。輸出型態決定用哪種損失。

迴歸

輸出一個連續數值 $\hat y$

損失：MSE（均方誤差）

例：預測頻寬、溫度

二元分類

輸出一個 logit $z$ → sigmoid → 機率 $p$

損失：BCE（二元交叉熵）

例：惡意 / 正常

多類分類

輸出多個 logits → softmax → 各類機率（總和 = 1）

損失：cross-entropy

例：貓 / 狗 / 鳥

自監督學習：答案可以從資料本身產生，不必人工標註。LLM 預訓練的答案，就是「這段文字的下一個 token」。

延伸閱讀：01 數學基礎 §3；05 §15.3

MSE 對應高斯誤差下的最大似然、交叉熵對應類別分布的最大似然：損失函數多半是負對數似然，不是隨便挑的。細節在 01 §3 與 09 附錄 D、F。

模型如何修正參數

損失 L
這一批資料錯了多少
↓ 反向傳播（鏈鎖律，由輸出往輸入逐層）
每個參數的梯度 ∂L/∂θ
該參數稍微變大，損失會變大還是變小、變多少
↓ 優化器（SGD／Adam）
更新後的參數
$\theta \leftarrow \theta - \eta\,\nabla_\theta L$（$\eta$：學習率）

反向傳播：負責「算」梯度

用鏈鎖律把損失對每個參數的影響一層層往回乘。

SGD／Adam：負責「用」梯度

SGD 照梯度方向走一步；Adam 再加上動量與每個參數各自的步長。

兩者不是同一件事：換優化器不必改反向傳播；反向傳播也不決定步長。

延伸閱讀：02 §5、§9；另見 01 §4.3

學習率是最常見的調不動元兇：太大會發散，太小會很慢。Adam 是常見的預設起點，但不代表永遠最好。

泛化與過擬合

  • Training set：用來學參數。
  • Validation set：用來選模型、超參數與分類門檻。
  • Test set：最後只用一次，估計模型在沒看過的資料上的表現。

控制過擬合的常見手段

  • 正則化（如 weight decay、dropout）
  • 資料增強、更多資料
  • Early stopping：驗證損失不再下降就停

訓練分數高 ≠ 模型好。同一批資料又用來調參又用來報成績，分數會被高估。

延伸閱讀：02 §6；06 評估與統計驗證 §19

分組資料（同使用者、同 session、同來源）要按群組切，否則同群組跨 train／test 會讓分數虛高。時間序列要按時間切。細節在 06 §19。

CNN 的完整資料流

同一個小 filter 滑過整張圖、權重共享：參數少，而且同一種圖案出現在哪裡都抓得到。逐層從邊緣、紋理組合出高階特徵。

延伸閱讀：03 CNN 與影像模型 §11

卷積就是滑動的內積：filter 是樣板，特徵圖是每個位置和樣板的對齊強度。維度與參數量的算法在 03 冊有完整的深度 5 範例。

小例子（示意）

文字今天天氣
token今天｜天氣（依 tokenizer 而異）

下一個 token最後位置分數最高者，例如「很好」

tokenization、embedding、Transformer、取樣是四個不同階段，不要混為一件事。

延伸閱讀：04 §12–14；05 §15–16

token 數是 API 計費與 context 長度的單位；每個字耗用幾個 token 依 tokenizer 與語言而異，估算成本要用目標模型的 tokenizer 實際計數。例子中的 id 是虛構示意。

Transformer 區塊

  • Q、K、V 由同一個輸入乘三個不同的權重矩陣投影出來。
  • 每個 head 算 masked scaled dot-product attention：Q 與 K 的內積 ÷ $\sqrt{d_k}$，未來位置在 softmax 之前遮掉。
  • 多個 head 拼接（concat）後乘 $W_O$。
  • 殘差、LayerNorm、FFN 組成一個完整區塊；堆 N 層。
  • 最後經 final norm 與 LM head，得到每個位置對詞表的 logits。

圖為常見的 decoder-only Pre-LN 配置，只是其中一種；原始 Transformer 用 Post-LN，也有模型改用 RMSNorm。

延伸閱讀：05 Transformer 與生成 §15.1–15.4

成本要分兩種：訓練／prefill 一次處理整段輸入，注意力約為 O(n²)；生成時每步只算一個新 token，搭配 KV cache，每步計算量隨既有長度近似線性增加，但 KV cache 的記憶體也隨長度線性增長（05 §15.4）。

樹和樹之間是相加，但每棵樹對特徵是非線性的：加法模型 ≠ 線性模型。

延伸閱讀：08 傳統 ML 與特徵工程：附錄 C

經典 GBM 擬合負梯度；XGBoost／LightGBM 再用二階資訊（Hessian）算分裂增益與葉值，相當於在每片葉子走一步牛頓法。新樹擬合的是「全部樣本」的梯度，誤差大的影響較大，不是只學錯的樣本。表格資料應把 GBDT 列入優先比較，但最終仍看目標資料上的驗證結果。

模型評估不只看 Accuracy

分類：分清錯在哪裡

  • Confusion matrix：抓對、誤報、漏抓各幾筆
  • Precision／Recall／F1：誤報與漏抓的取捨
  • ROC-AUC：整體區辨力
  • PR-AUC：只看正類；隨機基準約等於正類比例

機率品質：說 0.8 的，真有八成嗎？

  • Calibration：預測機率與實際比例是否一致
  • Brier score：機率與 0/1 結果的平方差
  • Reliability diagram：點落在對角線上 = 校準良好

三條規則

  • 門檻（threshold）在 validation set 選，凍結後才在 test set 評估一次。
  • 類別不平衡時看每個類別的指標與 PR-AUC；99.9% 都是正常時，99.9% accuracy 等於沒做事。
  • 同一測試集比較兩個模型，用配對方法（paired bootstrap、McNemar）；「打亂標籤」只能回答資料裡有沒有訊號。

延伸閱讀：06 評估與統計驗證 §18–19

一個數字只是樣本估計，要看信賴區間；CI 跨過門檻時應判「無法斷定」。p-value 是在虛無假設與檢定前提都成立時，觀察到至少同樣極端結果的機率，不是「結果只是運氣的機率」。

模型部署與硬體

  • GPU／NPU 擅長大量平行的矩陣與張量運算。
  • BF16／FP16 常用於混合精度訓練與推論（部分狀態仍保留 FP32）。
  • INT8／INT4 可降低權重與部分運算成本，但要驗證精度；支援的格式依硬體而異。
  • 記憶體不只有權重：還有 activation、KV cache、runtime buffer 與量化 metadata。

部署要一起評估延遲、吞吐、記憶體、功耗與準確度，並在目標硬體上實測。

延伸閱讀：07 硬體、數值格式與部署 §20；KV cache 見 05 §15.4

「訓練比推論貴」只對同一模型、同一批資料的單次步驟成立；參數量只能粗估計算量，實際成本還受序列長度、batch、稀疏性（如 MoE）與記憶體頻寬影響。部分層（如 embedding、LM head）可能保留較高精度。
