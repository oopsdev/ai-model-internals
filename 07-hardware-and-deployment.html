20. 浮點、量化與硬體加速

本節談硬體如何加速（§20.1）、數字用什麼格式存（§20.2）、以及如何用量化壓縮模型（§20.3）。

20.1 GPU/NPU 為什麼能加速 AI 計算

核心一句話：神經網路的前向與反向（微積分）幾乎全部化約成矩陣乘法 (matmul) + 逐元素運算，這兩種運算「大量、獨立、可同時做」——GPU/NPU 就是為此而生。

為什麼矩陣運算天生可平行。 矩陣乘法 $\mathbf{C}=\mathbf{A}\mathbf{B}$，每個輸出 $C_{ij}=$（A 第 $i$ 列）$\cdot$（B 第 $j$ 欄）是一個獨立內積，彼此不相干 → 可同時算。CPU 少數強核心偏序列；GPU 有數千個小核心，一次做數千個「乘加 (MAC)」，把大量獨立內積塞滿。

GPU 的加速手段：

手段作用
數千個 ALU同時做數千個乘加
Tensor Cores專用硬體，一個時脈算完一小塊矩陣乘
高頻寬記憶體 HBMTB/s 級頻寬餵大量矩陣資料
分塊 (tiling) + 片上 SRAM切小塊放快取重複用，少去慢速主記憶體
低精度 FP16/BF16/INT8每時脈算更多、頻寬省 → 吞吐倍增

NPU/TPU 更專精、更省電：

  • 脈動陣列 (systolic array)：一整片 MAC 單元排成網格，資料像水流過、每個單元邊流邊乘加 → 一次吞一大塊矩陣乘，能效比 GPU 更高。
  • 晶片面積大量用於乘加器，並常針對低精度運算最佳化 → 低功耗高吞吐，適合邊緣設備（代價是通用性低）。支援的數值格式依硬體而異：常見 INT8、INT4，也有 FP16、BF16 或混合精度。

反向傳播的「微積分」也是矩陣乘法。 以一層 $\mathbf{z}=\mathbf{W}\mathbf{x}$ 為例（鏈鎖律，§4.3）：

$$\text{前向：}\ \mathbf{z}=\mathbf{W}\mathbf{x}\qquad \text{反向：}\ \frac{\partial L}{\partial \mathbf{x}}=\mathbf{W}^\top\frac{\partial L}{\partial \mathbf{z}},\quad \frac{\partial L}{\partial \mathbf{W}}=\frac{\partial L}{\partial \mathbf{z}}\,\mathbf{x}^\top$$

反向兩式又都是 matmul；激活函數的導數是逐元素運算。所以「訓練 = 前向 matmul + 反向 matmul + 逐元素」，全是 GPU/NPU 的強項；自動微分 (autodiff) 就是把微分自動拆成這串可平行運算。

工程意涵。 ① 訓練 vs 推論：就同一個模型、同一批樣本或 token 而言，一次訓練步驟（前向＋反向＋更新）遠貴於一次推論，且訓練要重複多輪 → 對應「邊緣做推論、再訓練放中央」；但上線後的總推論量可能遠高於一次訓練。② 參數量只能粗估計算量：dense Transformer 推論每個 token 約 $2\times$ 參數量 FLOPs，可當直覺；實際成本還受序列長度、activation、稀疏性（如 MoE 每次只啟用部分參數）、batch、架構與記憶體頻寬影響。③ 量化（依硬體支援的格式，如 INT8 / INT4）可提高吞吐、降低記憶體 → 邊緣落地的關鍵之一。

20.2 浮點與數值格式

數字在電腦裡用固定位元存。常見格式（每參數位元組）：

格式位元每參數特點
FP32324 B全精度（1/8/23：sign/exp/fraction）；混合精度訓練中常用於主權重副本、優化器狀態與部分累加
FP16162 B半精度（1/5/10），範圍小、易溢位；混合精度訓練需搭配 loss scaling
BF16162 B腦浮點（1/8/7），範圍同 FP32、精度較低 → 現代加速器混合精度訓練常用
INT881 B整數，推論量化常用
INT440.5 B更激進，多用於權重量化（邊緣 / 本地部署）

訓練用什麼格式？ FP32 不是現代訓練的普遍預設：在支援的加速器上，常用 BF16 / FP16 混合精度 (mixed precision)——矩陣乘法以 16 位元計算，同時保留 FP32 的主權重副本、優化器狀態或部分累加，以兼顧速度與數值穩定。實際配置依框架與硬體而定。

浮點數 = sign（正負）＋ exponent（範圍）＋ mantissa（精度）。BF16 給更多 exponent（大範圍不溢位）、較少 fraction；FP16 相反（範圍小但精度略高）。註：正規化浮點有一個隱含的 leading 1，故有效尾數精度 ＝ fraction bits + 1（FP16 為 10+1、BF16 為 7+1）：

20.3 量化 (Quantization)

把權重/激活從 FP16 降到 INT8/INT4 表示：

  • 好處：權重儲存量相對 FP16 約 ÷2（INT8）～÷4（INT4）、頻寬省；硬體支援時整數運算更快。
  • 方法：PTQ（訓練後量化，快、免重訓）、QAT（量化感知訓練，較準但要重訓）。
  • 取捨：位元越低越省，但精度誤差越大，需權衡。

工程意涵。 量化是邊緣落地的關鍵之一。7B 權重若由 FP16 理論上降為 4-bit，純權重儲存量約由 14 GB 降至 3.5 GB；實際執行所需記憶體通常更高——還要加上 scale / zero-point 等量化 metadata（常以群組為單位存放）、KV cache（§15.4）、activation、runtime buffer 與框架 overhead，且部分層（如 embedding、LM head）可能保留較高精度（換算見 ai-background-knowledge §3.1）。邊緣 NPU 常提供 INT8 / INT4 等低精度加速，但支援格式依硬體而異，部署前要確認目標硬體支援哪些格式。
